# 架构说明

## 分层

```
┌──────────────────────────┐      ┌───────────────────────────┐
│  AppleVisionOCR.app (SwiftUI) │      │  applevision-ocr (Python CLI)  │
└────────────┬─────────────┘      └─────────────┬─────────────┘
             │ Process                          │
             └──────────────┬───────────────────┘
                            ▼
                 ┌────────────────────┐
                 │ applevision_ocr (包)    │  投票 / 版式 / 修正 / 参数
                 └─────────┬──────────┘
                           │ subprocess
                           ▼
                 ┌────────────────────┐
                 │ ocrvision (Swift)  │  PDFKit 渲染 + Vision 识别
                 └────────────────────┘
```

界面不重复实现任何识别逻辑，它只是把命令行包了一层：好处是两种入口行为永远一致，改一处两边都生效。

## 引擎：`src/engine/ocrvision.swift`

输入文件（PDF 或图片），输出逐行 JSON：

```json
{"p":1,"x":0.058,"y":0.042,"w":0.42,"h":0.021,"t":"能不能告诉我，中国的税负在世界是什么水平？"}
```

坐标全部归一化到 0–1，`y` 从上往下。这一步只做两件事：把页面变成位图、把位图变成带坐标的文本行。**不做任何版式判断**，所以它可以被别的程序单独使用。

几个实现要点：

- PDF 用 `PDFPage.draw(with:to:)` 渲染到 `CGContext`，倍率由 `--scale` 控制。
- 小图（长边 < 1600px）自动放大到 2000px 再识别，否则小字识别率明显下降。
- `--rot` 用 CoreImage 旋转整张位图，用于书里横排的大表。
- 输出按 `y` 再 `x` 排序；同一行内 `|Δy| < 0.006` 视为同一行。

## 投票：`src/applevision_ocr/voting.py`

同一页用 3.5 / 4.5 / 5.6 三个倍率各识别一次。单字错误随倍率变化，因此可以按位置投票。

对齐用 `difflib.SequenceMatcher` 逐字比，得到"列"（column），每列是一个 `Counter`，记录每个候选字被几路投中、以及几路没有这个字。

判定顺序：

1. 某个字票数唯一最高，且多于"空缺"票 → 取它。
2. 否则若候选里出现「的」→ 取「的」。这是刻意的偏置：Vision 把「的」漏掉的概率远高于凭空多出一个「的」。
3. 否则若候选里出现「的」的已知误识字（钓、哟、菂、旳、酌、时）→ 取「的」。
4. 否则取票数最高的非空字符。

两个容易踩的坑，都已写进测试：

- **对齐串必须用"非空字符"重建**。若直接拿含空缺的字符串去对齐，同一字符会被插入两次，输出「的的」。
- **空缺不删字**。只要有任意一路看到某个字就保留。Vision 漏字比造字常见，删字的损失更大。

页面级兜底：如果某页投票后的总字数不到最完整那一路的 85%，说明行切分不一致，直接采用那一路的结果，避免截断。

## 版式：`src/applevision_ocr/layout.py`

只依赖坐标和字号，不需要知道具体文档：

| 特征 | 判据 | 处理 |
| --- | --- | --- |
| 页眉页脚 | 跨页重复（数字归一后比对）或位于顶端/底端且含数字 | 剔除 |
| 段落 | 左边界比正文基准线右移 | 另起一段 |
| 跨页段落 | 页首行未缩进 | 续接到上一段 |
| 脚注 | 字号 < 正文中位数的 0.72 且位于页面下部 | 收进文末【注释】 |
| 表格 | 短行占比 > 45% 且短行数 ≥ 8 | 按 x 聚类成列、y 聚成行，输出 `|` 分隔 |
| 图表 | 行首匹配 `图 1-1` / `Figure 1` | 输出占位说明，丢弃散落的坐标标签 |

正文基准线取该页长行的 x 众数；缩进阈值在基准线之上取一个自适应值（不超过 0.030），避免不同排版的书用同一个常数。

## 修正：`src/applevision_ocr/fixes.py`

Vision 在中文印刷体上有稳定的偏差，规则只收"左边不是词"的组合，因此可以无条件替换：

- `钓/哟/菂/旳 → 的`（但 `钓鱼/垂钓` 保留）
- `进人/收人/陷人… → 进入/收入/陷入…`（只收动词搭配，`送人` 这类真词不动）
- `竟争→竞争`、`债劵→债券`、`欢盟→欧盟`、`AT→AI`（仅在中文或引号之间）

要加规则，往 `RULES` 里加一行 `(错, 对)` 即可。

## 扩展点

- **换语言**：`--lang` 直接传给 Vision；引擎侧没有语言相关的逻辑。
- **加版式规则**：`layout.py` 里每个特征是一个独立函数，加一条判断即可。
- **别的入口**：引擎的 JSON 输出是稳定的，任何语言都能接。

## 性能

单页成本 ≈ 渲染 + Vision 推理。3 路投票意味着 3 倍成本，实测书页约 2.4 秒/页，单页图片 0.9 秒。`--no-vote` 降到约 0.8 秒/页。

想再快，可以按页并行跑多路识别（当前是串行的），代价是内存和 Vision 的并发调度。
